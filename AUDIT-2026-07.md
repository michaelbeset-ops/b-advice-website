## 1. Security

### HOOG — Brevo API-key hoort nooit in client-side code
`docs/contact/index.html:224` en `docs/locatieaanvraag/index.html:263`:

```js
var BREVO_KEY = 'BREVO_API_KEY'; // Vervang met jouw Brevo API key
```

De code is zo opgezet dat je een échte Brevo-key in de publieke HTML plakt. Doe dat
nooit: een Brevo API-key geeft volledige accounttoegang (mail versturen namens jou,
contactlijsten uitlezen). Zolang de placeholder er staat wordt de bevestigingsmail
nooit verstuurd — het is dus dode code én een valkuil.
**Fix:** verwijder het Brevo-pad volledig en gebruik de ingebouwde autoresponder van
Web3Forms, of zet een klein server-side proxy'tje ertussen (bijv. Cloudflare Worker)
waar de key als secret staat.

### HOOG — Formulieren hebben geen spam-/misbruikbescherming
De Web3Forms access-key (`28c0f073-…`, `docs/contact/index.html:223`) is per definitie
publiek, maar er is geen honeypot, geen CAPTCHA en geen domeinbinding. Iedereen kan de
key scrapen en jouw maandelijkse inzendquotum opmaken of je inbox volspammen.
**Fix:**
1. Zet in het Web3Forms-dashboard domein-restrictie op `b-advice.info`.
2. Voeg het `botcheck`-honeypotveld van Web3Forms toe aan beide formulieren.
3. Overweeg hCaptcha (native ondersteund door Web3Forms) op de locatieaanvraag.

### HOOG — Foutafhandeling formulier verbergt mislukte verzendingen
`docs/contact/index.html:257` en `docs/locatieaanvraag/index.html:308`: de `fetch` naar
Web3Forms wordt niet gecontroleerd op `response.ok`. Als de API een fout teruggeeft
(quotum op, key geblokkeerd) ziet de bezoeker tóch "verzonden" — en ben je een lead
kwijt zonder het te weten. **Fix:** check de JSON-response (`success: true`) voordat je
het succesbericht toont.

### HOOG — Login-link naar B-Organized via onversleuteld HTTP
3× `href="http://b-organized.info"` in elke pagina (o.a. `docs/index.html:65,82,180`).
Een login-link over HTTP is gevoelig voor omleiding/MITM op publieke netwerken.
**Fix:** overal `https://` (en `rel="noopener"` bij `target="_blank"`).

### MIDDEN — Geen security headers mogelijk op GitHub Pages
GitHub Pages ondersteunt géén custom headers: geen CSP, geen HSTS, geen
X-Frame-Options, geen Referrer-Policy. Voor een statische brochuresite is het risico
beperkt (geen sessies/cookies om te stelen), maar clickjacking en het ontbreken van
HSTS blijven open.
**Fix-opties:** (a) Cloudflare (gratis tier) vóór de site zetten en headers daar
instellen, of (b) migreren naar Cloudflare Pages/Netlify (`_headers`-bestand). Zet
minimaal in GitHub Pages-settings "Enforce HTTPS" aan. Een
`<meta http-equiv="Content-Security-Policy">` is een gedeeltelijke tussenoplossing.

### MIDDEN — Publieke repo bevat interne bestanden
De repository is **public**. Naast de site zelf staan er: volledige
design-chattranscripten (`chats/chat1.md`, 853 regels), `email-preview.html`,
`uploads/` (o.a. originele teamfoto's), `b-advice-theme.zip` (1,1 MB) en interne
B-Organized-taakbord-URL's (`docs/rmn-*/`, ook zichtbaar in `docs/404.html`).
**Fix:** repo privé maken (GitHub Pages blijft werken op een betaald plan) óf de
niet-site-bestanden verwijderen/verplaatsen. Controleer ook dat de
`b-organized.info/board/houten/tasks/...`-URL's achter een login zitten — de
QR-kortlinks zijn bewust publiek, maar het bord zelf mag dat niet zijn.

### HOOG (compliance) — Privacyverklaring klopt niet met de werkelijkheid (AVG)
- `docs/privacy/index.html:120` noemt **EmailJS** met "(VS, Privacy Shield)" als
  verwerkingsgrond. Privacy Shield is in 2020 ongeldig verklaard (Schrems II) — deze
  grondslag bestaat niet meer.
- De site gebruikt feitelijk **Web3Forms** (en straks Brevo); die worden nergens
  genoemd. `docs/cookies/index.html:116` noemt ook nog EmailJS.
- De cookiebanner belooft "analytische cookies met uw toestemming", maar er draait
  helemaal geen analytics — de keuze "Alles accepteren" doet niets anders dan
  "Alleen noodzakelijk".
- **Google Fonts** wordt geladen vanaf Google-servers (IP-doorgifte naar de VS;
  in de EU herhaaldelijk als AVG-schending beoordeeld) en staat niet in de verklaring.

Voor een bedrijf dat aan gemeenten levert is een kloppende AVG-huishouding een
gunningsfactor. **Fix:** verklaring herschrijven rond de echte verwerkers (Web3Forms,
GitHub Pages, evt. Brevo), Google Fonts zelf hosten, en de banner laten kloppen met wat
er werkelijk gebeurt (zonder analytics kan de banner zelfs weg of veel kleiner).

### OK
- Geen hardcoded secrets gevonden (de Web3Forms-key is bedoeld als publiek).
- Geen `.env`-bestanden of gevoelige configs in de gepubliceerde map.
- Geen dependencies/build-chain → geen npm-kwetsbaarheden.
- WordPress-theme (`b-advice-theme/`) is netjes (geen eval/injecties; versienummer en
  emoji-scripts verwijderd) maar lijkt ongebruikt legacy — zie "Onderhoud".

## 2. Performance

### HOOG — Logo van 604 KB op elke pagina
`docs/assets/b-advice-logo.png` is 1920×559 px / 604 KB en wordt getoond op 40 px
hoogte — én gebruikt als favicon én als apple-touch-icon. Elke paginaweergave laadt
ruim een halve MB voor een logo. Er staat al een `b-advice-logo.svg` in `uploads/`.
**Fix:** SVG gebruiken (of een 120px-brede PNG van ~5 KB) + apart klein favicon.

### HOOG — Hero-afbeelding niet geoptimaliseerd (LCP + CLS)
`docs/assets/dashboard.png`: 1920×1440 px / 640 KB, above the fold op de homepage
(2× gebruikt: `docs/index.html:121,184`). Geen `width`/`height`-attributen (→ layout
shift), geen `fetchpriority="high"`, geen modern formaat.
**Fix:** exporteer als WebP (~80–100 KB), zet expliciete `width`/`height`, geef de
hero-versie `fetchpriority="high"` en de tweede instantie `loading="lazy"`.

### MIDDEN — Teamfoto's 1707×2560 met EXIF-data
`docs/assets/team/*.jpg` (3× ~190 KB) worden klein weergegeven op /over-ons/.
**Fix:** verkleinen naar ±800 px hoogte, EXIF strippen, `loading="lazy"`.

### MIDDEN — Render-blocking Google Fonts met 7 gewichten
Elke pagina laadt DM Sans (6 gewichten + italic) én DM Mono via
`fonts.googleapis.com`. **Fix:** zelf hosten (woff2, alleen de 3–4 gebruikte
gewichten) — lost meteen het AVG-punt op. `display=swap` staat al goed.

### LAAG — Geen `loading="lazy"` op below-fold afbeeldingen
Nergens gebruikt; goedkoop toe te voegen op nieuwsafbeeldingen, teamfoto's, tweede
dashboard-afbeelding.

### OK
- Geen frameworks, geen zware scripts, één klein CSS-bestand (36 KB), inline JS
  minimaal. De basis is snel — de afbeeldingen zijn vrijwel het hele probleem.

## 3. UX & Design

### HOOG — Homepage rendert in quirks mode
`docs/index.html:1`: er staat een `<script>` (de rmn-redirectmap) **vóór**
`<!DOCTYPE html>`. Browsers negeren dan de doctype en vallen terug op quirks mode,
met onvoorspelbare CSS-verschillen (o.a. box-sizing/height-gedrag). Bovendien is het
script daar dood gewicht: op de homepage is het path altijd `/`, en `docs/404.html:7-13`
handelt de rmn-kortlinks al af. **Fix:** verwijder het hele blok uit
`docs/index.html` (2 KB minder, geldige HTML terug).

### MIDDEN — Dode links
- Footer op álle pagina's: `<a href="#">Disclaimer</a>` (`docs/index.html:249`) —
  pagina bestaat niet. Maak de pagina of haal de link weg.
- `/over-ons/`: 3 LinkedIn-knoppen bij teamleden met `href="#"`
  (`docs/over-ons/index.html:128,146,164`). Echte profiel-URL's invullen of weghalen —
  een knop die niets doet schaadt vertrouwen precies op de "mensen"-pagina.

### MIDDEN — Conversiepad locatieaanvraag onderbelicht
De hoofdnav heeft 9 items; "Locatieaanvraag" (een primaire conversiepagina) staat
onopvallend tussen de informatiepagina's. De hero-CTA's verwijzen naar /diensten/ en
/b-organized/, de CTA-band alleen naar /contact/. **Suggestie:** maak van
"Locatieaanvraag" een visueel onderscheiden knop in de nav (naast Contact) en voeg op
/diensten/-subpagina's een directe CTA "Vraag een locatiebeoordeling aan" toe.

### LAAG — Hamburger-menu via JS in plaats van CSS
`docs/index.html:261`: de hamburger wordt getoond/verborgen met een
`window.innerWidth`-check + resize-listener. Een `@media`-regel in CSS is robuuster
(geen flits bij laden, werkt zonder JS).

### OK
- Heldere informatiearchitectuur, consistente nav/footer op alle pagina's.
- Hero: sterke propositie, duidelijke primaire + secundaire CTA, stats als social
  proof. Goede above-the-fold indruk (zodra de afbeeldingen geoptimaliseerd zijn).
- Breakpoints op 1024/768 px aanwezig; mobiel overlay-menu met body-scroll-lock werkt.

## 4. SEO & vindbaarheid

### OK — de basis is opvallend goed op orde
- Alle 23 pagina's hebben unieke `<title>`, meta description, canonical, en
  Open Graph/Twitter-tags.
- Structured data: `Organization` (home), `Article` op alle 5 nieuwsartikelen,
  `BreadcrumbList` op dienstenpagina's.
- `docs/sitemap.xml` (23 URL's) komt 1-op-1 overeen met de bestaande mappen;
  `docs/robots.txt` verwijst ernaar en sluit de `rmn-*`-kortlinks uit, die zelf ook
  `noindex, nofollow` + meta-refresh hebben. 404-pagina heeft `noindex`. Netjes.

### MIDDEN — og:image is het (transparante) logo
`og:image` verwijst overal naar `b-advice-logo.png` (1920×559, transparant, 604 KB).
Op LinkedIn/WhatsApp geeft dat een lelijke of lege preview — juist voor B2B-shares
relevant. **Fix:** maak één 1200×630 og-afbeelding (logo op donkergroene achtergrond
met tagline) en verwijs daarnaar; voor nieuwsartikelen per artikel een eigen beeld.

### LAAG — Interne linkstructuur nieuws
Nieuwsartikelen linken naar diensten, maar dienstenpagina's linken niet terug naar
gerelateerde artikelen. Een blokje "Gerelateerd nieuws" op dienstenpagina's versterkt
topical authority.

## 5. Toegankelijkheid

### MIDDEN — Kleurcontrast onder WCAG AA
- `--ink-4: #7a9585` op de lichte achtergrond (`#FAFAF9`) ≈ **3,1:1** — faalt AA
  (4,5:1) voor kleine tekst. Gebruikt voor o.a. de "Contact"-navlink (13 px,
  `docs/style.css:61`) en stat-labels.
- Footertekst `rgba(255,255,255,.45)` op `#0f1e16` ≈ **4,0:1** — net onder AA
  (`docs/style.css:132`).
**Fix:** `--ink-4` verdonkeren naar bijv. `#5f7a6a` en footer-tekst naar `.6` opacity.

### MIDDEN — Zwakke focus-indicatie op formuliervelden
`docs/style.css:275-276`: `outline: none` op inputs, alleen een groene borderkleur als
focus-state. Voor toetsenbordgebruikers is dat moeilijk te zien. **Fix:** voeg een
zichtbare focusring toe, bijv. `box-shadow: 0 0 0 3px var(--green-light)`.

### MIDDEN — Interactieve elementen zonder ARIA-state
- Hamburgerknop heeft `aria-label="Menu"` ✓ maar geen `aria-expanded` die meebeweegt.
- FAQ-accordeons (`.faq-q`) hebben geen `aria-expanded`/`aria-controls`; nergens in
  `docs/` komt `aria-expanded` voor.

### LAAG — Geen skip-link
Voeg een "Naar inhoud"-link toe als eerste element voor toetsenbord-/screenreader-
gebruikers.

### OK
- Alle afbeeldingen hebben alt-teksten; `lang="nl"` staat op elke pagina; alle
  formuliervelden hebben gekoppelde `<label for>`; verplichte velden gebruiken
  `required` + `type="email"`.

## 6. Onderhoud / codebase-hygiëne (bonus)

- **MIDDEN — Dubbele codebases.** De root bevat een verouderde generatie van de site
  (`Contact.html` met EmailJS, eigen `sitemap.xml`, `shared.css`, `shared-footer.js`)
  én een WordPress-theme (`b-advice-theme/` + zip) die niet meer overeenkomen met wat
  live staat in `docs/`. Groot risico dat toekomstige wijzigingen in de verkeerde
  bestanden belanden. **Fix:** archiveer of verwijder alles buiten `docs/` dat niet
  meer gebruikt wordt (of verplaats het naar een `archive/`-map met README).
- **LAAG — Geen `.gitignore`** aanwezig.
- De rmn-redirectmap staat op twee plekken (`docs/index.html` én `docs/404.html`);
  na de fix hierboven blijft alleen `404.html` als bron over — voeg nieuwe
  rmn-nummers dus alleen dáár en als map toe.
